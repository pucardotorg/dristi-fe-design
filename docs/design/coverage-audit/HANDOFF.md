# Handoff: feedback coverage board

Last updated 30 Oct 2026. Branch `feature/coverage-board` on pucardotorg/dristi-fe-design,
cut from main 0ab02ff. No PR. Do not merge as is: the board is for the owner and the lead
designer to decide, and the product fixes ride along as its "after" examples.

## Why this exists

The feedback-states rollout (PRs #174–176, #178) left many screens on the old style. The
owner found "Remove from office" without its mark and asked for proof of everything still
missing, then for a board showing before and after so the decisions can be made per
pattern, not per screen.

## What is on the branch

1. **Product fixes** (commit "first fixes, one or two per pattern"). Real changes that the
   board uses as "after" examples. Listed in the commit message.
2. **The board** at `/coverage-board` (`apps/dristi-app/src/app/coverage-board/`):
   - `data.ts`: generated by `docs/design/coverage-audit/build.js` from `combined.json`
     (three auditors) + `review.json` (independent review). Don't hand-edit; rerun the builder.
   - `examples.ts`: the before/after pairs per pattern. `after: null` shows a box that says why.
   - `page.tsx`, `canvas.tsx`: the board (pan, zoom, jump bar, Skip / Different call marks).
   - Screenshots in `apps/dristi-app/public/coverage-board/{before,after}/`.
3. **Audit data** in `docs/design/coverage-audit/`: inventory, results, review, the builder,
   and the capture scripts (`cap.mjs` + `lib.mjs`, flows in `flows/`).

## How to run and capture

- Build and serve this checkout as production (dev caches filled the disk twice): in
  `apps/dristi-app`, `npx next build` then `npm run start -- -p 4701` (or `.claude/launch.json`
  entry `ds-bump-prod`). Open `/coverage-board`.
- Capture: start headless Chrome on its own port (9371), then
  `node cap.mjs flows/<file>.json`. Writes half-scale JPGs to `public/coverage-board/after/`.
  Radix menus need a `pointerdown` event, not `click` (see `flows/f12.json`).
- Pushing: this Mac's refs folder has `Feature/` with a capital F, so push with
  `git push origin HEAD:refs/heads/feature/coverage-board`.

## How the owner decides

Every example and every card has Agree / Keep as today / Different call plus a note box.
Decisions are saved in that browser's localStorage (`coverage-board-decisions`). "Copy
decisions" at the top puts a plain-text list on the clipboard to paste into the chat.

Owner feedback so far (30 Oct): the "after" for "Mobile number verified" (big StatusLine) is
too heavy; the old small green line looked right. Recommended: a 16px `StatusMark` + words
(the small inline mark the app already uses next to receipts and uploads), and one line of
DS guidance for quiet field-level confirmations. The 16px version is now built on the branch
(14a1eb59); the DS guidance is not written yet (see DS-GUIDANCE-GAP.md).
